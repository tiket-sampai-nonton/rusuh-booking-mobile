ROOT CAUSE
----------
src/providers/providers.tsx and query-client.ts used a runtime
`require("@tanstack/react-query")` guarded by try/catch, because the package
was not a declared dependency (RBT-004 placeholder). tsc + jest passed (jest
virtual-mocked the module), but `npx expo export --platform web` FAILED: Metro
statically resolves requires at bundle time and could not resolve the module.

FIX
---
1. `npm install @tanstack/react-query@5` (added to dependencies).
2. query-client.ts: removed the dynamic require + null-return guard; now
   `import { QueryClient } from "@tanstack/react-query"` and
   createQueryClient() returns a real QueryClient.
3. providers.tsx: normal import of QueryClient + QueryClientProvider; composes
   SafeAreaProvider (initialMetrics so children render on the first frame /
   synchronously in jsdom) -> QueryClientProvider -> ServiceProvider.
4. Updated the two provider tests to assert the real import behaviour
   (they previously asserted the now-removed "returns null when absent" path).
