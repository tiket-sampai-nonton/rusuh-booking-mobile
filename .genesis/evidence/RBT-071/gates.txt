ACCEPTANCE CRITERIA (AC1)
================================================================
- getTickets → one card per ticket: the Success screen renders N ETicketCards
  from the confirmed ticketCount (one card + QR each). The QR payload is a SAFE
  reference `RBT|<bookingId>|<n>` (ticketRef) — NEVER a raw NIK/token/PII (D7.1);
  a test asserts no 16-digit NIK renders. QR drawn with react-native-svg via
  react-native-qrcode-svg (web + native). ✓
- native file-system + share: useETicketShare on native writes a text manifest
  (safe refs only) to the cache dir and hands it to expo-sharing's share sheet. ✓
- web Blob/print: on web it opens a print window with the manifest (save-as-PDF). ✓
- The e-tickets show ONLY under the RBT-070 verified-PAID branch (never on an
  unverified deep-link). ✓

Clean-Arch: ETicketCard + useETicketShare live in presentation; ticketRef is a
pure helper; platform modules (expo-file-system/expo-sharing) are required
LAZILY inside the native default so importing the hook loads nothing on web/test.
