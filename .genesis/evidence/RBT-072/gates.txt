================================================================
- permission: ExpoNotificationAdapter.requestPermission() checks the current
  grant, prompts only when needed. ✓

  permitted, null on denial / mint failure (no projectId / simulator) — never
  throws. ✓
- required flows (notification-flows domain rule, pure): expiry_reminder →
  /payment/<booking>, payment_success → /success/<booking>, admission →
  /checkout/<session>, event_reminder → /events/<event>. Bahasa copy; schedule
  time carried for the time-based ones. ✓
- tap → deep link: scheduleLocal carries {deepLink, kind} in the notification
  data; useNotifications' tap listener resolves the route via the pure
  notificationRoute rule and router.push()es it (only in-app "/" paths — an
  external URL is refused). ✓
- platform split: native binds ExpoNotificationAdapter; web binds the mock until
  web-push (RBT-073); the shared flow rule is identical on both (D6.1). The
  NotificationBridge is mounted in the root layout, inside the providers.

Clean-Arch: notification-flows + notificationRoute are pure domain; the port is
unchanged in shape (LocalNotification gained kind + deepLink); expo-notifications
is touched ONLY by the adapter + the hook's tap listener, both requiring it
lazily so web/test load nothing.
