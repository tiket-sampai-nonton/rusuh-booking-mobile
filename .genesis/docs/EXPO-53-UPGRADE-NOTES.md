# Expo SDK 53 upgrade — review notes

This branch upgrades the Expo-aligned React, React Native and tooling versions from SDK 52 to SDK 53, updates the Loader ref for React 19 types, and switches the native JS engine from JSC to Hermes after simulator validation.

The initial dependency alignment encountered an optional peer conflict for `react-server-dom-webpack`; a diagnostic install using `--legacy-peer-deps` produced the lockfile. A subsequent clean `npm ci` without that flag succeeded. Reconfirm peer resolution in CI; do not rely on the diagnostic flag silently.

Checks run locally: clean `npm ci` (including the fail-closed transitive compatibility patch); `npx expo install --check`; typecheck; ESLint (warnings remain); production dependency high-severity audit; full Jest/RNTL coverage; Android Hermes debug compile and emulator smoke; iOS Hermes simulator build and launch; static web export. The audit gate now passes with zero high/critical findings; one low and 17 moderate production findings remain.

Before merging: inspect PR CI output and review the React/React Native/Expo changes and new native runtime. Local Android and iOS simulator builds and launch smokes passed, but full booking/payment flow QA, physical-device QA, and release-signing validation remain outside this SDK migration check. The static web export passes; this does not satisfy the separate web-release SEO and bundle gates (public route budget: 300 KB gzip; transactional route budget: 500 KB gzip). SDK changes require a new native build and cannot be shipped to old binaries as an OTA update.

Android Hermes debug build: `./gradlew assembleDebug --no-daemon` succeeded after regenerating the Android project from Expo config (`hermesEnabled=true`). The APK contains `libhermes.so` for all four ABIs. The app installed and navigated Home → Browse → event detail on the Pixel_7_Pro_Edited emulator without a runtime exception. Screenshot and run notes are in `.genesis/evidence/RBT-121/`. iOS JSC launched into a runtime exception in React Native's reduce-motion check (`undefined is not a constructor`). An isolated Hermes simulator build required the SDK 53 Expo Router `origin` config; after setting that and fixing the required TanStack Query provider wiring, the app launched and rendered its home screen on an iPhone 16 Pro simulator. These are smoke checks, not full booking-flow QA.

An SDK 54 diagnostic migration was explored separately and produced additional TypeScript errors involving expo-file-system and Reanimated; it was not adopted into this candidate. The requester approved the SDK 53 live evidence under G3. PR CI checks and broader native booking-flow validation remain before release readiness.

A temporary Expo config plugin patches fmt during iOS pod installation to disable `FMT_USE_CONSTEVAL` as an Xcode compatibility workaround. This disables fmt's compile-time format checking. The patch and tradeoff were reviewed; the plugin fails closed if its expected Podfile or fmt patch pattern disappears. Remove the workaround when upgrading to a React Native/fmt release that fixes the upstream issue. An unsigned arm64 iOS simulator build on Xcode 26.6 succeeded and the app launched with Hermes. Native booking flow QA remains outstanding.

The locked SDK 53 Metro/PostCSS versions had two high advisories. To keep the SDK aligned while satisfying the repo's high-severity audit gate, `package.json` pins `postcss@8.5.23` and `image-size@2.0.3` through npm overrides. Metro 0.82 expects the v1 `image-size` API, so `scripts/patch-transitive-security.cjs` adapts its asset dimension call to v2's named buffer and async file-path APIs. The script is a `postinstall` step, validates Metro remains 0.82.x, and fails closed if the import/call site changes. Clean `npm ci`, `npm audit --omit=dev --audit-level=high`, and static web export pass; the audit reports zero high/critical findings, with one low and 17 moderate production findings remaining.
